# راهنمای IPv6 در Luffy Lite

این راهنما مکمل README اصلی است. پشتیبانی IPv6 از کتابخانه استاندارد Python استفاده می‌کند و وابستگی جدیدی ندارد.

## آدرس سرور در لینک اتصال

| نام | توضیح | پیش‌فرض |
|---|---|---|
| `VLESS_HOST` | میزبان قابل دسترس برای اتصال WebSocket؛ با تنظیم این متغیر می‌توان مقصد پیش‌فرض لینک را جایگزین کرد. | خالی؛ نام میزبان صفحه در مرورگر استفاده می‌شود |

در نبود متغیر محیطی `VLESS_HOST` یا در صورت خالی بودن آن، لینک نمایش‌داده‌شده و کپی‌شده از نام میزبان صفحه در مرورگر استفاده می‌کند. در دامنه‌های پیش‌نمایش با پسوند `.build.reflexsandbox.com`، پیشوند `3000-` یا `8080-` به `8000-` تبدیل می‌شود. میزبان ثابتی به‌عنوان پیش‌فرض تنظیم نشده است. برای مقصد عمومی، میزبان لینک، پارامتر `host` و SNI یکسان هستند؛ پورت ۴۴۳، TLS و انتقال WebSocket استفاده می‌شوند. مسیر پیش‌فرض `/ws/Luffy` است و در لینک به‌صورت `%2Fws%2FLuffy` رمزگذاری می‌شود؛ نام مسیر و fragment با `VLESS_NAME` تغییر می‌کنند. لینک محلی از پورت ۸۰۰۰ و WebSocket بدون TLS استفاده می‌کند. فرم ورود آدرس در صفحه وجود ندارد.

استفاده از نام میزبان صفحه یا نگاشت دامنه پیش‌نمایش به‌تنهایی مسیر WebSocket را در دسترس قرار نمی‌دهد. در صورت نیاز، `VLESS_HOST` را به میزبانی تغییر دهید که اتصال WebSocket روی مسیر مربوطه واقعاً در آن کار می‌کند. مقدار URL کامل HTTPS نیز قابل استفاده است؛ پورت و مسیر URL ورودی جایگزین پورت و مسیر ثابت لینک نمی‌شوند.

## پیش‌نیاز اتصال عمومی

تنظیم IPv6 در `VLESS_HOST`، سرویس غیرقابل دسترس را قابل دسترس نمی‌کند. میزبان باید واقعاً IPv6 عمومی، مسیر شبکه و دسترسی ورودی مناسب داشته باشد و WebSocket سفارشی سرویس را در دسترس قرار دهد. برای لینک عمومی، TLS و گواهی معتبرِ مورد قبول کلاینت برای همان IPv6 یا نام میزبان لازم است؛ یک گواهی مخصوص دامنه لزوماً IPv6 خام را پوشش نمی‌دهد. دامنه دارای رکورد AAAA و گواهی مطابق با دامنه نیز قابل استفاده است. دستگاه کلاینت هم باید به شبکه IPv6 دسترسی داشته باشد.

این قابلیت تضمینی درباره پشتیبانی IPv6 یا WebSocket سفارشی در Reflex Cloud یا هیچ میزبان دیگری نیست؛ امکانات واقعی میزبان باید جداگانه بررسی شوند. لینک loopback فقط به همان دستگاه کلاینت اشاره می‌کند.

## مقصدهای TCP خروجی

آدرس نوع ۳ در هدر VLESS تنها با ۱۶ بایت کامل پذیرفته می‌شود و با `ipaddress.IPv6Address` به شکل فشرده تبدیل می‌شود. اتصال TCP برای IPv6 literal صریحاً از خانواده `AF_INET6` استفاده می‌کند. IPv4 و نام دامنه همچنان از اتصال معمول asyncio استفاده می‌کنند؛ حل DNS دامنه می‌تواند رکورد AAAA را انتخاب کند.

هدرهای ناقص، طول آدرس ناکافی، دامنه غیرقابل رمزگشایی، فرمان غیر-TCP و پورت صفر رد می‌شوند، نه اینکه باعث IndexError یا خطای decoder شوند. هدر باید در نخستین پیام باینری WebSocket کامل باشد؛ هدر ناقص بین پیام‌های جداگانه بازسازی نمی‌شود. رفتار relay و مدیریت قطع اتصال معمول WebSocket حفظ شده است. دسترسی IPv6 خروجی نیز نیازمند پشتیبانی واقعی شبکه سرور است.
